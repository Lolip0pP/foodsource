# FoodSource

**Поиск и сравнение поставщиков продуктов питания.** FoodSource помогает быстро составить список компаний, к которым можно обратиться с запросом о поставке.

Пользователь указывает продукт и, при необходимости, город. Сервис ищет сайты потенциальных поставщиков, собирает опубликованные на них сведения и показывает сравнительные карточки с объяснением оценки. Например: «мука пшеничная высшего сорта оптом», город — Казань.

> Это прототип для демонстрации идеи, а не готовая система закупок. Информация извлекается с публичных сайтов, может быть неполной или устаревшей. Перед заказом нужно уточнить условия непосредственно у поставщика.

## Что умеет прототип

- Искать сайты поставщиков через Yandex Search API.
- Извлекать со страниц название компании, товары, цену и единицы измерения, минимальный заказ, доставку, регионы, контакты и сертификаты — если такие сведения опубликованы.
- Искать по категории товара (список в интерфейсе) и по городу доставки. Город сопоставляется с регионом поставщика по границам слов, чтобы «Смоленская область» не считалась Москвой.
- Загружать не только страницу из выдачи, но и до трёх служебных страниц того же сайта (контакты, доставка, сертификаты): в каталоге этих сведений обычно нет.
- Проверять извлечённые сведения по исходному тексту страницы и не показывать данные, которые не удалось подтвердить.
- Сравнивать найденные предложения и объяснять, какие сведения повлияли на оценку, а каких данных не хватает.
- Показывать ход обработки запроса.

Отсутствие сведений не означает плохие условия: например, если цена не указана на сайте, сервис не считает её нулевой. Чем меньше критериев удалось найти, тем сильнее занижается итоговый балл, а такая карточка помечается «мало данных»: 100 баллов по одному найденному критерию были бы обманчивы. Оценка помогает сориентироваться, но не заменяет проверку компании и коммерческого предложения.

## Как посмотреть

**Живой прототип:** https://lolip0pp.github.io/foodsource/ (страница `demo.html`, публикуется workflow `.github/workflows/pages.yml`; нужно один раз включить Settings → Pages → Source: GitHub Actions).

В проекте есть две HTML-страницы:

- **`demo.html`** — сохранённый демонстрационный пример. Не требует API-ключей или запущенного бэкенда. Это снимок реального прогона: данные статичны, а оценки пересчитаны по текущей формуле.
- **`front.html`** — интерфейс для отправки запросов в работающий FoodSource API. Для него нужны запущенный бэкенд и настройки Yandex Cloud.

Инструкция по запуску приложения ниже.

## Запуск поиска с API

### Что понадобится

- Python 3.10 или новее.
- Аккаунт Yandex Cloud с доступом к Yandex AI Studio и Yandex Search API.
- `YANDEX_FOLDER_ID` и API-ключ с областями `yc.ai.foundationModels.execute` и `yc.search-api.execute`. В исходной конфигурации также указаны роли `ai.languageModels.user` и `search-api.webSearch.user`.

### Установка и настройки

В PowerShell из папки проекта создайте и активируйте виртуальное окружение, установите зависимости и скопируйте пример настроек:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` и укажите свои `YANDEX_FOLDER_ID` и `YANDEX_API_KEY`. При необходимости задайте отдельный ключ для поиска в `YANDEX_SEARCH_API_KEY`; если его не задавать, используется основной ключ. Остальные параметры в `.env.example` имеют значения по умолчанию.

### Запуск приложения

В одном окне PowerShell запустите API:

```powershell
uvicorn app.main:app --reload
```

В другом окне PowerShell, также из папки проекта, запустите локальный сервер HTML-страниц:

```powershell
python -m http.server 5500 --bind 127.0.0.1
```

Откройте <http://127.0.0.1:5500/front.html>. Адрес API по умолчанию — `http://127.0.0.1:8000`. Проверить доступность API можно по адресу <http://127.0.0.1:8000/health>, а интерактивную документацию — <http://127.0.0.1:8000/docs>.

Если интерфейс открыт с другого адреса, добавьте его origin в `CORS_ORIGINS` в `.env` — например, `https://username.github.io`. Origin включает протокол и домен, но не путь страницы.

### Как проходит запрос

1. Интерфейс отправляет запрос с названием продукта и, если нужно, городом.
2. API запускает поиск и возвращает номер фоновой задачи.
3. Сервис собирает страницы поставщиков, извлекает сведения и формирует сравнительные оценки.
4. Интерфейс показывает результат и основания для сравнения.

Поскольку внешние сервисы обрабатывают запросы в фоновом режиме, результат может появиться не сразу. Поиск и обработка страниц используют квоты и могут тарифицироваться Yandex Cloud. Повторные результаты временно кэшируются в памяти приложения на 24 часа.

## Тесты

Основные тесты выполняются локально, без сетевых запросов и ключей:

```powershell
python -m pytest -q
```

## Оценка качества извлечения

`evaluation/` содержит 12 размеченных примеров страниц и скрипт, который считает precision, recall и F1 по каждому полю:

```bash
python -m evaluation.run_eval          # без ключей: базовый вариант без LLM
# с YANDEX_API_KEY и YANDEX_FOLDER_ID извлечение выполняет YandexGPT, как в сервисе
```

Примеры синтетические (написаны вручную по типичным страницам), поэтому набор подходит для проверки логики и сравнения
версий между собой, но не как оценка качества на реальных сайтах. Для неё нужно разметить настоящие страницы.
Базовый вариант без LLM находит контакты точно, но не извлекает цену, минимальный заказ и доставку.
Сертификаты определяются по словарю и дают ложные срабатывания на упоминаниях («многие внедряют ХАССП»).

| Файл или папка | Назначение |
|---|---|
| `demo.html` | Статичная демонстрация с сохранённым примером |
| `front.html` | Интерфейс, который отправляет запросы в API |
| `app/main.py` | HTTP API и подключение внешних сервисов |
| `app/pipeline.py` | Последовательность поиска, сбора и оценки сведений |
| `app/search.py` | Поиск через Yandex Search API |
| `app/fetch.py` | Загрузка HTML-страниц с учётом `robots.txt` |
| `app/extract.py` | Извлечение сведений с помощью YandexGPT |
| `app/grounding.py` | Проверка извлечённых сведений по тексту страницы |
| `app/scoring.py` | Оценка и ранжирование предложений |
| `app/models.py` | Структуры запросов и результатов |
| `app/config.py` | Чтение настроек из окружения и `.env` |
| `app/jobs.py`, `app/cache.py` | Фоновые задачи и кэш в памяти |
| `tests/` | Тесты основной логики и последних доработок |
| `evaluation/` | Размеченные примеры и подсчёт precision/recall |
| `.github/workflows/` | Публикация демо на Pages и прогон тестов |
| `.env.example` | Шаблон локальной конфигурации без секретов |

## Ограничения

- Сертификаты определяются как упоминание на странице, а не как подтверждённый документ: сервис не проверяет их подлинность.
- Служебные страницы подбираются по словам в адресе и тексте ссылки («контакты», «доставка», «сертификаты»). Сайты с нестандартными названиями или с содержимым, подгружаемым скриптами, дадут меньше данных.

- Результаты зависят от того, какие сведения поставщик опубликовал на сайте и какие страницы доступны для загрузки.
- Цены сравниваются только при совпадении единиц измерения; пересчёта упаковок нет.
- Сервис не проверяет фактическую надёжность поставщика, актуальность цены, наличие товара или подлинность сертификатов.
- Оценки и отзывы пользователей не собираются.
- Фоновые задачи и кэш хранятся в памяти: после перезапуска приложения они не сохраняются. Это упрощённый вариант для прототипа, не для промышленной эксплуатации.
- Одна задача может занять несколько минут: внешние сервисы работают асинхронно, а создание поисковых операций ограничено квотами Yandex Cloud.
